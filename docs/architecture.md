## One render, end to end (CLI)

```mermaid
sequenceDiagram
  participant main as Glimpse_cli main()
  participant reg as scenes/registry
  participant R as Renderer::renderScene
  participant T as worker thread (one row band)
  participant I as rayColor (integrators)
  participant F as Film / Image
  main->>reg: findScene(name) → make()
  main->>main: applyOptions (spp, width, depth) → cam.initialize()
  main->>R: renderScene(scene, image)
  R->>R: cam.initialize(), build BVHNode over scene.world
  par one per hardware thread
    R->>T: renderSection(rows [start, end))
    loop each stratified cell (sqrtSpp²), each row, each pixel
      T->>I: rayColor(cam.getRay(u, v), ..., maxDepth)
      I-->>T: radiance sample
      T->>F: film.addSample(i, j) · image.setFloat(i, H−1−j, sRGB(mean)) (live view)
    end
  end
  R-->>main: all threads joined
  main->>F: film.linearRGB() → writePFM (.pfm) or encodeSRGB(exposure).write (.png)
```

The viewer drives the same `renderScene` from a background thread (`gui/raytracer.h`) and uploads the `Image`
as a texture every frame while it renders.

## One bounce of `rayColor`

The RTIOW / TROYL recursive estimator that techniques 07–09 replace. Each call returns a one-sample estimate of
the radiance arriving along the ray.

```mermaid
flowchart TD
  start(["rayColor(ray, depth)"]) --> d{"depth < 0?"}
  d -- yes --> black["return 0"]
  d -- no --> hit{"world.hit<br/>t in (0.001, ∞)?"}
  hit -- no --> bg["return background"]
  hit -- yes --> emit["Le = mat.emitted(...)"]
  emit --> sc{"mat.scatter?"}
  sc -- no --> retE["return Le"]
  sc -- "yes, specular<br/>(skipPdf)" --> spec["return attenuation × rayColor(skipPdfRay, depth−1)"]
  sc -- "yes, diffuse" --> lights{"scene has lights?"}
  lights -- yes --> mix["sample MixturePDF<br/>(½ light pdf + ½ material pdf)"]
  lights -- no --> mat["sample material pdf"]
  mix --> est
  mat --> est["return Le + attenuation × scatteringPdf × rayColor(scattered, depth−1) / pdf"]
```

## Conventions worth a picture

**Image orientation.** Camera `v` and Film rows `j` count up from the bottom, while `Image` rows and image files
count down from the top. The renderer flips once, when it writes. The Stage 0 "upside-down images" bug was this
flip hidden in the viewer instead.

![image orientation](diagrams/image_orientation.svg)

**Stratified pixel samples.** The renderer's `sampleSquareStratified` places one jittered sample in each of the
`sqrtSpp × sqrtSpp` sub-cells. That's also why `--spp 10` renders 9 samples.

![stratified samples](diagrams/stratified_samples.svg)

**Cosine-weighted directions.** `CosinePDF` samples `randomCosineDirection`, whose density is `cos θ / π`. That
puts more samples near the normal, where a Lambertian surface's integrand is largest. Seen from above, the samples
are uniform over the disk (Malley's method).

![cosine-weighted hemisphere sampling](diagrams/cosine_hemisphere.svg)
